\section{Developing the scanner and parser in F\#}
Integer-C is the input language.
The compiler's host language is F\# and its target is JVM/Jasmin assembly.
The grammar and Integer-C sample above therefore retain their original notation.
The frontend turns that syntax into typed records and union cases.
@@snippet:compiler-types@@

The grammar is stored in small Larkita files in the directory \texttt{Grammar}; the lexical files and the rules for programs and lists are those of the original course.
Keywords are found as identifiers and then retyped, longer comparison operators are complete tokens, and comments are ignored.
The statements add two \texttt{for} loops; the dangling else is resolved in favour of shifting and thus belongs to the nearest unmatched conditional.
@@snippet:compiler-statements-grammar@@

The expression grammar encodes the precedence of the ternary operator, the Boolean operators, the comparisons and the arithmetic operators with one variable per level.
@@snippet:compiler-expressions-grammar@@

The frontend converts the abstract syntax tree returned by Larkita into the typed AST and desugars both loops into assignments and \texttt{while} loops.
Syntax errors raise \texttt{UnexpectedInput} with line and column.
@@snippet:compiler-frontend@@

\href{../../Chapter-12/Compiler.ipynb}{\nolinkurl{Chapter-12/Compiler.ipynb}} prints the token stream and AST before code generation.
This separates lexical errors, syntax errors and backend errors.
The source examples include the original sum, factorial and prime-number programs, plus precedence and ternary-expression checks.

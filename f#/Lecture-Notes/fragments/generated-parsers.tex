\chapter{Using Larkita as a parser generator \label{chapter:ply}}
Larkita, Karl Stroetmann's light-weight version of Lark, generates a canonical LR(1) parser from a grammar in EBNF notation.
This edition uses its F\# port \texttt{Support/Larkita}.
A grammar file contains both the tokens and the rules, but no semantic actions: the abstract syntax tree follows from the grammar.
The string literals of an alternative form the \emph{head} of the tree, while all other symbols become its children; an alternative consisting of a single symbol passes the tree of this symbol through.
The F\# port returns these trees as nested tuples of the type \texttt{nested}: a leaf \texttt{Leaf (Str s)} holds a string, and a node \texttt{Node [...]} holds the list of its components.

The grammar file contains the rules and imports the tokens \texttt{CNAME}, \texttt{NUMBER} and \texttt{WS} from Larkita's library.
@@snippet:calculator-grammar@@

The alternative \texttt{expr "+" product} yields the tuple \texttt{("+", l, r)}, the assignment \texttt{IDENTIFIER ":=" expr ";"} yields \texttt{((":=", ";"), ("IDENTIFIER", x), e)}, and \texttt{\%ignore "(", ")"} removes the parentheses from the head of a parenthesized expression.
The grammar's separate product and factor nonterminals encode arithmetic precedence structurally.

The environment is an immutable map from names to values.
Assignment returns a new environment; a lookup either finds a value or reports an undefined variable.
The evaluator therefore has an explicit state boundary.

\section{Implementing a simple interpreter \label{chapter:interpreter}}
The source language has assignments, blocks, conditionals, loops and calls to predefined functions.
This source language is distinct from the F\# program that interprets it.
@@figure:ply-yacc-interpreter:fig:Pure.g@@
@@figure:ply-yacc-interpreter:fig:sum.sl@@
The example computes $\sum_{i=1}^{n^2} i$ and prints the result.
The grammar \texttt{sl.lark} determines the abstract syntax trees; the directive \texttt{\%ignore: "(", ")", "\{", "\}", ";"} removes the punctuation from the heads of all trees.
@@snippet:interpreter-grammar@@
The interpreter matches these nested tuples directly: the first component of a tuple names the statement or the operator.
@@snippet:interpreter-types@@
@@snippet:interpreter-build@@

Evaluation receives a map of values and an explicit I/O record.
Integer literals, input, addition, subtraction and multiplication retain arbitrary-precision integers.
The simple language uses true division, which returns a floating-point value; modulo follows Python's floor-quotient rule, including negative operands.
Mixed integer/real comparisons preserve integer precision.
That record is the actual boundary between deterministic evaluation and reading or printing.
Undefined variables and unsupported constructs produce diagnostics rather than fabricated values.
@@snippet:interpreter-evaluate@@

Execution returns the updated map.
A block folds over its statements; a loop recursively threads its current map through its body.
This makes the loop invariant visible in both the type and the control flow.
